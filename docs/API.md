# MedClue API

## 1. API overview

The MedClue API handles medication identification, CIMA verification and official uses processing. The Android app communicates with the backend through HTTPS. Responses use JSON.

API documentation is automatically generated by FastAPI and available at `/docs` and `/redoc`. The OpenAPI specification is available at `/openapi.json`.

## 2. Endpoints

### POST /identify

Starts identification from a photo. The Android app sends `multipart/form-data` with one required file field, `photo`.

Supported types are JPEG (`image/jpeg`), PNG (`image/png`) and WebP (`image/webp`). The file must not be empty or larger than 15 MB (15,728,640 bytes).

Examples use test data. Response examples show only relevant fields; unused fields are described in section 3. Example HTTP 200 response with two AI candidates:

```json
{
  "status": "multiple_matches",
  "candidates": [
    {"name": "Example", "strength": "500 mg", "form": "tablet"},
    {"name": "Another", "strength": null, "form": null}
  ]
}
```

### POST /verify

Checks a selected match or continues a failed step without repeating image analysis. The request uses `application/json` with exactly one of these non-null fields:

| Field | Type | Purpose |
| --- | --- | --- |
| `candidate` | Object | Search CIMA using an AI candidate selected by the user. |
| `national_code` | String | Load the selected CIMA presentation by its national code. |
| `retry_token` | String | Continue from the failed step stored in a returned token. |

A candidate requires `name`, `strength` and `form`. The name must be a nonempty string. Strength and form must be nonempty strings or `null`; include both fields even when unknown. Codes and tokens must be nonempty strings. Extra JSON fields are rejected.

AI candidate selected in the app:

```json
{"candidate": {"name": "Example", "strength": "500 mg", "form": "tablet"}}
```

CIMA presentation selected in the app:

```json
{"national_code": "000010"}
```

Retry request. The placeholder represents the token returned by the backend:

```json
{"retry_token": "<returned_retry_token>"}
```

Example confirmed response, HTTP 200:

```json
{
  "status": "verified",
  "medication": {
    "name": "EXAMPLE 500 mg COMPRIMIDOS",
    "strength": "500 mg",
    "form": "comprimido",
    "registration_number": "000001",
    "national_code": "000010"
  },
  "official_uses": ["Supported use"]
}
```

## 3. Response structure

Both endpoints return all these fields. Unused optional values are `null`; unused lists are empty.

| Field | Type | Purpose |
| --- | --- | --- |
| `status` | String | Identification outcome, listed below. |
| `medication` | Object or null | Confirmed CIMA medicine. Present only with `verified`. |
| `suggested_candidate` | Object or null | Unconfirmed suggestion kept for review or further action. |
| `candidates` | List of objects | AI candidates awaiting user selection. |
| `presentations` | List of objects | CIMA options awaiting user selection. |
| `official_uses` | List of strings | English use labels for a confirmed medicine. May be empty. |
| `failed_step` | String or null | Step that failed; see the retry table. |
| `retry_token` | String or null | Backend-issued token used to continue that step. |

CIMA objects add `registration_number` and `national_code` to the candidate fields. Both identifiers are strings. A `multiple_matches` response has at least two entries in either `candidates` or `presentations`, never both.

## 4. Response statuses

These are identification results returned with **HTTP 200**, including service failures.

| Status | Meaning and when returned |
| --- | --- |
| `verified` | CIMA confirms the medicine. Official uses are included when available. |
| `multiple_matches` | Several AI candidates or CIMA presentations need user selection. |
| `not_identified` | AI returns no reliable medicine name. CIMA is not queried. |
| `no_match` | A suggested medicine cannot be confirmed through CIMA. This includes insufficient matching information. |
| `connection_error` | An external request fails or its response cannot be used. This can include a provider's own request timeout. |
| `timeout` | The shared 40-second backend processing limit is reached before confirmation. |

If CIMA has already confirmed the medicine, a failure or timeout while loading or translating uses keeps `status` as `verified`. The response includes the confirmed `medication`, an empty `official_uses` list, `failed_step` and `retry_token`. An empty use list without retry information means no use labels are available for this result.

## 5. Error handling

HTTP errors mean the request could not be processed as a normal identification result. They use a `detail` field rather than the response structure above.

| HTTP code | When returned |
| --- | --- |
| `400` | Empty photo or an invalid, changed or expired retry token. |
| `404` | The selected CIMA presentation is not found. |
| `413` | The photo exceeds the size limit. |
| `415` | The uploaded file has an unsupported media type (only JPEG, PNG and WebP are accepted). |
| `422` | Request validation fails: missing photo, invalid JSON fields or types, or missing or conflicting `/verify` choices. |
| `499` | The handler detects a client disconnection and stops processing. The disconnected client may not receive this response. |
| `503` | The identification service has not been initialized. |

Example HTTP 413 body:

```json
{"detail": "The photo is too large."}
```

For HTTP 422, `detail` is a list of validation errors. A connection failure or client-side timeout may end without any JSON response.

## 6. Retry mechanism

The app uses the result and `failed_step` to choose the retry request:

| Result or failed step | Next request |
| --- | --- |
| `not_identified` or `image_analysis` failure | Send the photo again to `POST /identify`. No retry token is returned. |
| `cima_verification` | Send the returned token to `POST /verify`; image analysis is not repeated. |
| `official_uses_retrieval` | Send the token to `POST /verify`; the medicine stays confirmed. |
| `uses_translation` | Send the token to `POST /verify`; the confirmed medicine and previously loaded CIMA text are reused. |

The app returns the latest token unchanged, as the only choice in the `/verify` body. Tokens are signed, but not encrypted, and expire after 15 minutes. They do not contain the photo.

Invalid, changed or expired tokens return HTTP 400 and require a new identification. If no response arrives, the app can repeat the original request; without a token, completed work may be repeated.
